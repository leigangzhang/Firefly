# 轻量化家庭影院资源下载工具方案文档

> 版本：v6（2026-10-20）。本版取代早期的"Web 核心 + 薄插件 + 淘宝买断"方案，以及 v5 的授权码收费方案。
> 依据：[目标市场定位分析](archive/目标市场定位分析.md)。
> 2026-10-24 按代码现状（0.3.0.0）校对：发布版不内置资源站和关键词；Torznab / Jackett 已放弃；插件不绕过人机验证。

## 1. 产品定位与核心理念

*   **目标用户**：首发面向中国大陆有 Mac/NAS 和 Jellyfin（后续加 Emby）的家庭影院用户，**不要求用户会翻墙**；他们缺乏折腾 *arr 等重度技术栈的能力。第二阶段做海外版，卖点是比 *arr 轻量。
*   **产品定位**：一款**开箱即用、极简闭环**的影视资源发现与自动化下载工具。片库在用户自己的硬盘里，不卡、不跑路、没有月费。
*   **商业模式**：**全部开源，没有任何收费环节**，靠好用形成口碑和传播。不开赞助入口，star 数上来后再决定。
*   **核心理念（做减法）**：
    *   **放弃重度规则**：不做复杂的关键词正则和打分选种，把过滤交给上游精选站点，由用户在版本列表里自选。
    *   **站点由用户自己添加**：发布版不内置、不推送任何资源站点和关键词；用户在配置页粘贴网址，插件自动识别。
    *   **轻资产**：不自建资源存储，不做服务器中转，不做部署服务。
    *   **少揽活**：一次只支持一种平台组合；用自检页、FAQ 和社区互助压低支持成本。

## 2. 架构：插件即核心

通过 Jellyfin 插件库安装，全部逻辑放在插件内（.NET），不再有独立的 Web 服务。

```
Jellyfin（Mac 版或 NAS Docker 版）
 └─ FireFly 插件
     ├─ 注入层：改写 /web/index.html，加入"发现 / 获取资源"入口
     ├─ API 层：插件 Controller 提供 /FireFly/api/*
     ├─ 核心层 FireFly.Core（与宿主无关）
     │   ├─ 资源源：按规则文件请求资源站，解析标题
     │   ├─ 元数据：TMDb 热门榜单与详情
     │   ├─ 下载器：IDownloader → 迅雷（Mac）/ qBittorrent（NAS）
     │   └─ 归档：规范命名 → 同盘移动 → 刷新媒体库
     └─ 宿主适配层（IMediaHost）：Jellyfin，后续 Emby
```

*   **核心与宿主分离**：`FireFly.Core` 不引用 Jellyfin 包，以后做 Emby 只需再写一个宿主适配层。
*   **相对 v5 的改动**：
    1.  **去掉授权与额度**：移除 `Licensing/`、`tools/FireFly.LicenseTool` 和额度界面。
    2.  **规则体系**：站点规则从 `DiaoSource` 代码中抽成数据文件（格式见 [规则文件格式](规则文件格式.md)），内置一份默认规则，放在主仓库。内置规则只含迅雷临时后缀、扩展名、TMDb 地址和榜单筛选目录，不含任何资源站和关键词。
    3.  **TMDb 入口**：默认使用 `api.tmdb.org`（实测大陆可直连；`api.themoviedb.org` 不可达），接口和图片地址在配置页下拉选择（已去掉代理，361685c）；API Key 由用户自己申请后填入。
    4.  **预告片可选**：YouTube 连不上就隐藏，后续参考豆瓣的做法获取。
    5.  **自检与日志**：配置页一键自检（TMDb 接口和图片、下载器、媒体库目录权限、规则可用性），并提供导出日志按钮。目前只有 TMDb 自检接口（`/FireFly/selfcheck/tmdb`）和每个站点的"测试"按钮，其余未做。

## 3. 核心功能链路

打造"发现 → 下载 → 归档"的闭环：

1.  **资源发现**：TMDb 热门榜单 + 搜索，展示海报、简介、年份和别名；预告片可选。
2.  **搜索**：在用户添加的站点里按片名和优选关键词搜索，结果不够再降级为只搜片名；版本列表显示标题、体积、分辨率、做种数，由用户自选。
3.  **下载与监控**：一键提交下载器，显示进度和速度；停滞时提示换版本。
4.  **自动归档**：下载完成后按 Jellyfin 规范重命名，同盘移动到媒体库目录，并触发媒体库刷新。

## 4. 资源规则与防屏蔽

*   **内置规则**：默认规则随开源代码发布，不含任何资源站和关键词。
*   **添加站点**：配置页只需粘贴站点网址或一次搜索的结果页网址，插件自动识别是 JSON 接口站还是网页站点（`jsonApi` / `html`），预览后添加；可按资源类型分配站点、拖动排优先级、单独测试。
*   **用户规则**：用户可以覆盖内置规则、添加自定义规则或订阅地址。需要适配的复杂场景：
    *   站点换域名或失效后的提示与更新；
    *   多套规则的合并与优先级；
    *   规则格式升级后的兼容；
    *   第三方规则的安全校验。
*   **镜像域名轮换**：规则中维护备用域名列表，默认用上次可用的域名，失效时自动切换。
*   **不做**：Torznab / Jackett / Prowlarr（2026-10-22 放弃：实测磁力质量差，也解决不了人机验证）；绕过人机验证或接口签名，这类站点识别时直接提示不支持。

## 5. 下载引擎

*   **Mac：迅雷（默认）**：插件执行 `open magnet:` 交给 Mac 迅雷，通过文件系统判断进度。迅雷 SDK 目前只支持 HTTP(S)，等它支持磁力再接入。美国 IP 实测无法用迅雷下载，所以海外版不用迅雷。
*   **NAS：qBittorrent**：公开发布前加入适配器，支持飞牛、绿联等 NAS 上的 Docker 版 Jellyfin。
*   **网盘离线 + STRM（后期附加）**：磁力提交到 115/PikPak 离线下载，再用 STRM 入库。只服务网盘会员用户，等网盘存储用户明显上升再做。

## 6. 开源、合规与风险控制

*   **代码托管**：同时开源到 GitHub 和 Gitee（大陆可达）。Gitee 对公开仓库有内容审核，遇到问题再拆规则仓库。
*   **完全不收费**：侵犯著作权罪以"以营利为目的"为前提，完全免费能消除最重的风险。剩余风险：GitHub DMCA 投诉、民事帮助侵权，整体较低。
*   **宣传口径**：只说"家庭媒体库管理、自动整理、本地播放不卡"，不提片名和资源站。
*   **元数据**：TMDb Key 由用户自己申请（非商业使用）；`api.tmdb.org` 被屏蔽后由社区维护可用入口。
*   **坚决不碰**：
    1.  **自建存储或共享库**：会变成重资产，法律风险急剧放大。
    2.  **任何收费**（买断、订阅、代注册 TMDb Key、赠送规则）。
    3.  **广告变现**和**部署服务**（靠人力，放大不了）。
*   **运营商风险**：不利用用户带宽做商业分发，避免触发 PCDN 管制。

## 7. 执行路线图

每个阶段只有达到门槛才进入下一阶段；没达到就停在当前阶段，继续作为自用工具。工期是粗估。

| 阶段 | 内容 | 工期 | 进入下一阶段的门槛 |
| --- | --- | --- | --- |
| 1. 改造与自用 | 第 2 节的改动 1–5；v5 的 M1–M3 实测；Mac + Jellyfin + 迅雷 | 2–3 周 | 自己连续用 2 周，全流程在不翻墙的大陆网络下走通 |
| 2. 种子用户 | 开源到 GitHub 和 Gitee、FAQ、用户群；官网初版（Cloudflare Pages）；邀请 10–20 位 Mac 用户 | 2–3 周 | 种子用户大多能自己装好；反馈的问题大多能靠自检定位 |
| 3. 公开发布 | qBittorrent 适配器和 NAS Docker 支持（先覆盖飞牛、绿联）；Emby 兼容；官网 SEO；在 V2EX、恩山、小红书、什么值得买发布 | 3–4 周 | 发布后按用户需求和反馈迭代 |
| 4. 海外版 | 英文资源接入方式（待定，不再走 Torznab）、英文界面、英文官网；在 r/jellyfin、r/selfhosted 发布 | 3–4 周 | 视反馈而定 |
| 后期可选 | 网盘离线 + STRM、剧集追更、动漫 | — | 用户需求明显上升时再做 |

**官网**：与公开版同时上线，内容为功能介绍、Mac/飞牛/绿联安装教程、插件库地址、TMDb Key 申请教程；SEO 关键词用"Jellyfin 插件""NAS 家庭影院""自动入库追更"，不用片名和资源站。
