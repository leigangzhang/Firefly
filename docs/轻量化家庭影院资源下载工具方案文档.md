# 轻量化家庭影院资源下载工具方案文档

## 1. 产品定位与核心理念

*   **目标用户**：拥有 NAS 及 Jellyfin/Emby 等家庭影院系统，但缺乏折腾 *arr 等重度技术栈能力的“中轻度用户”。
*   **产品定位**：一款**开箱即用、极简闭环**的影视资源发现与自动化下载工具。
*   **核心理念（做减法）**：
    *   **放弃重度规则**：摒弃复杂的关键词正则、打分选种逻辑，将过滤工作交给上游精选站点。
    *   **拥抱精选策略**：通过维护 10 个以内的核心优质站点，覆盖 70% 以上的热门影视、剧集、动漫和纪录片。
    *   **轻量资产**：不自建资源存储，保持轻资产运营。

## 2. 架构选型：Web 核心 + 薄插件

为了同时兼容 Jellyfin、Emby 甚至 Plex，并保证未来的扩展性，建议采用以下架构：

*   **独立 Web 应用（核心）**：所有搜索、榜单聚合、下载调度、文件归档的逻辑均放在独立的 Web 服务端。支持通过浏览器直接访问操作。
*   **薄插件（壳）**：为 Jellyfin/Emby 编写轻量级插件。插件仅负责：注入 UI 入口、提供 API 桥接、获取宿主媒体库路径、触发媒体库刷新。
*   **优势**：业务逻辑只维护一套，插件开发成本极低，未来即便不依赖家庭影院宿主，也能作为一个纯粹的 Web 工具独立运行。

## 3. 核心功能链路

打造“发现 -> 下载 -> 归档”的丝滑闭环：

1.  **资源发现**：
    *   聚合展示精选站点的热门榜单。
    *   结合 TMDb/豆瓣 API，自动拉取高质量的海报、简介、年份和别名。
2.  **智能搜索**：
    *   根据 TMDb 元数据自动提取搜索词（主标题、原语言标题、年份）。
    *   内置简单的预设“画像”（如：电影-画质优先、动漫-简日双语），替代复杂的用户自定义关键词。
3.  **下载与监控**：
    *   一键提交下载任务，内置进度条展示。
    *   失败/死种自动降级重试（获取备用磁力）。
4.  **自动归档与刮削**：
    *   下载完成后，按 Plex/Jellyfin 规范自动重命名。
    *   生成软链接/硬链接放入媒体库目录（避免破坏下载端的做种），并触发媒体库刷新。

## 4. 上游资源获取与防屏蔽策略

由于上游多为盗版站点，面临关停、换域名、反爬等必然风险，需采取**多级降级策略**：

*   **规则云端热更新**：将站点的域名、解析规则放在 GitHub 等云端 JSON 文件中。客户端启动时拉取，一旦站点变更，无需发布新版本插件，云端更新一次即可全网生效。
*   **镜像域名轮换**：维护已知的备用域名列表，默认使用上次可用的域名，失效时自动切换。
*   **允许用户自定义**：在高级设置中开放站点 URL 修改权限。当官方维护跟不上时，允许极客用户自行修改，降低客诉率。
*   **反爬对抗（可选）**：集成 `FlareSolverr` 的原理（无头浏览器），用于绕过部分站点的 Cloudflare 盾。但需明确，这只能提高访问成本，无法根本解决针对性屏蔽。

## 5. 下载引擎选型：迅雷 SDK 与本地兜底

*   **首选：迅雷 SDK**：
    *   利用迅雷庞大的 P2P 网络和云端离线下载能力，实现“云端下载，本地回传”，终端无需长时间在线，下载速度有保障。
*   **备用：本地下载器（Aria2/qBittorrent）**：
    *   当迅雷 SDK 受限或用户偏好开源时，支持对接用户本地 NAS 上的下载器。插件负责调度和发送磁力，存储和带宽完全由用户侧承担。

## 6. 商业化演进与风险控制

*   **变现路径（早期）**：
    *   **买断制**：通过淘宝、闲鱼等渠道销售 Pro 版授权（解锁全部精选站点、自动归档等高级功能）。符合目标用户“为省心付费”的意愿。
    *   **返佣**：引导用户开通迅雷会员以使用云端加速，与迅雷开放平台洽谈渠道分成。
*   **规模化演进（P2P 加速与 P 站雏形）**：
    *   用户量增长确实能提升基于迅雷网络的 P2P 下载效率。
    *   **坚决不碰的雷区**：
        1.  **自建存储**：买服务器囤积资源会将“轻工具”变成“重资产”，成本极高且法律风险急剧放大。
        2.  **广告变现**：影视盗版站无法接入正规品牌广告，灰色广告会摧毁产品定位。建议采用“赞助者”模式（付费获得优先队列等特权）而非卖广告。
*   **合规与运营商风险**：
    *   产品面向小众、高付费意愿群体，通过非公开渠道销售，能一定程度降低版权风险。
    *   警惕 PCDN 管制：如果插件利用用户闲置带宽进行大规模商业分发，可能触发运营商限速。建议控制策略，或依赖迅雷已有的合规网络。

## 7. 执行路线图建议 (Roadmap)

*   **Phase 1 (MVP)**：搭建 Web 核心，硬编码 2-3 个稳定站点，实现热门榜单展示 + 迅雷 SDK 一键下载。
*   **Phase 2 (闭环)**：实现下载后的规范化重命名与 Jellyfin 目录硬链接，开发 Jellyfin/Emby 薄插件实现入库刷新。
*   **Phase 3 (稳定)**：实现规则云端热更新、镜像轮换，加入本地下载器（Aria2）作为备用兜底。
*   **Phase 4 (商业)**：完善授权系统，上架淘宝/闲鱼，引入简单的质量画像（画质优先/体积优先）供用户选择。
