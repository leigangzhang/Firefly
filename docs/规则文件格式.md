# 规则文件格式

FireFly 把会随上游变化的东西都放在规则文件里：搜索源的地址和响应格式、优选关键词、迅雷临时文件后缀、视频 / 字幕扩展名、热门榜单的筛选目录、配置页里可选的 TMDb 地址。站点换域名或改字段时只改规则，不用改代码、不用发版。

## 加载顺序

1. **内置规则**：`src/FireFly.Core/Rules/rules.default.json`，编进插件 DLL，随插件版本更新。
2. **本地覆盖**：插件数据目录里的 `rules.json`（Jellyfin.app 默认为 `~/Library/Application Support/jellyfin/plugins/FireFly.Jellyfin`），可选。
3. **配置页设置**：插件配置页"资源站点""优选关键词"里的改动，保存在插件配置的 `RulesOverlay` 字段里，格式和 `rules.json` 相同（只写改动的部分），叠加在最上层。配置页"高级"里可以导出、导入、清空这一层。

三层都改完即生效，不用重启 Jellyfin：插件每次用规则时（最多每 2 秒检查一次）发现配置页设置或 `rules.json` 的修改时间变了，就重新加载并清空搜索缓存。

上一层按字段**叠加**到下一层上，只需要写要改的部分：

| 位置 | 叠加方式 |
|---|---|
| 对象（如 `thunder`、`discover`、某个源的 `response`） | 逐个字段覆盖，没写的字段保留内置值 |
| `sources` 数组 | 按 `name` 合并：同名的源只覆盖写到的字段；新名字追加在内置源之后 |
| `keywords.items` 数组 | 按 `word` 合并：同一个词只覆盖写到的字段；新词追加在后面 |
| 其他数组（如 `keywords.disable`、`sourceOrder`、`discover.companies`） | 整体替换 |

以下情况会忽略覆盖文件、使用内置规则，并在配置页"高级"里的提示中说明原因：

- `rules.json` 不是合法 JSON；
- `format` 高于插件支持的格式版本（说明规则是给更新的插件写的，需要升级插件）；
- 文件没有 `format` 字段且 `version` 低于内置规则版本：这是 0.2 及以前整份拷贝出来的旧规则，叠加上去会把新版内置规则改回旧的。

类型不认识、缺少 `endpoints` 或 `response.itemsPath` 的源会被跳过，同样显示在配置页"高级"的提示里。

## 版本字段

- `format`：文件结构的版本，当前为 `1`。只有不兼容地改结构时才加一；旧插件看到更高的 `format` 会拒绝读取。覆盖文件可以不写，按 `1` 处理。
- `version`：内置规则内容的版本，每次改 `rules.default.json` 加一。覆盖文件里的 `version` 不参与叠加。

## 搜索源（`sources[]`）

有三种类型：

- `jsonApi`：按 GET 请求一个返回 JSON 的搜索接口，按路径取出种子列表和字段。
- `torznab`：Jackett / Prowlarr 的 Torznab 接口，格式固定，只需要地址和 API Key，见下文。
- `html`：没有数据接口、搜索结果直接写在网页里的站，用 CSS 选择器读结果页，见下文。

站点的顺序就是搜索优先级：越靠前的站点，结果排得越靠前（同一关键词下）。顶层 `sourceOrder`（站点名数组）可以重排站点，没列出的站点保持原顺序排在后面；配置页拖动排序写的就是它。

| 字段 | 说明 | 默认 |
|---|---|---|
| `name` | 源的名字，也是覆盖时的合并键 | 必填 |
| `kind` | `jsonApi`、`torznab` 或 `html` | 必填 |
| `endpoints` | 同一个源的多个镜像地址，依次尝试，上次成功的排到最前 | 必填 |
| `pageSize` / `maxPages` | 每页条数、最多翻几页 | 10 / 1 |
| `enabled` | 设成 `false` 可停用一个站点（如 `rules.json` 里写的站点） | `true` |
| `types` | 这个站负责的资源类型：`movie` 电影、`tv` 剧集、`anime` 动漫、`variety` 综艺、`documentary` 纪录片；空数组表示全部 | `[]` |
| `apiKey` | 只用于 `torznab` | 空 |
| `request.keywordParam` / `limitParam` / `offsetParam` | 查询参数名 | `keyword` / `limit` / `offset` |
| `request.maxLimit` | 站点允许的单页上限，`pageSize` 超过时截断 | 10 |
| `response.statusPath` / `statusOk` / `messagePath` | 业务状态码路径、成功值、错误信息路径；`statusPath` 为空表示不检查 | 空 / `"200"` / 空 |
| `response.itemsPath` | 种子列表所在路径 | 必填 |
| `response.hasMorePath` | "还有下一页"标志路径；为空时本页取满就继续翻 | 空 |
| `response.fields.*` | 每一项里的字段路径：`infoHash`、`name`、`magnet`、`size`、`createdAt`、`files`（数组，其中每项用 `filePath`、`fileSize`） | `hash`、`name`，其余为空 |
| `response.fields.createdAtFormat` | `unix`（秒）、`unixms`（毫秒）或 `iso` | `unix` |

路径用点分隔，如 `data.torrents`。`magnet` 取不到时用 `infoHash` 拼磁力；`infoHash` 也可以是磁力链接或 32 位 Base32，会统一成 40 位十六进制；数字字段接受数字或数字字符串。

### Torznab

```json
{ "name": "Jackett", "kind": "torznab", "endpoints": ["http://127.0.0.1:9117/api/v2.0/indexers/all/results/torznab/"], "apiKey": "…" }
```

`endpoints` 直接填 Jackett 的"Copy Torznab Feed"或 Prowlarr 索引器的地址，末尾没有 `/api` 时会自动补上。请求为 `t=search&q=关键词&limit=100&offset=…&extended=1&apikey=…`。只收有 `infohash` 属性或磁力链接的条目；只给 `.torrent` 下载地址的条目没法交给迅雷的磁力流程，会跳过。接口返回 `<error>`（如 API Key 不对）时报为这个站点的错误。

### 网页站点（html）

```json
{
  "name": "example.org", "kind": "html",
  "endpoints": ["https://example.org/search?keyword={keyword}&p={page}"],
  "maxPages": 1,
  "html": { "item": "ul.list > li", "title": ".t a", "link": ".t a@href", "detail": true }
}
```

`endpoints` 是地址模板：`{keyword}` 换成搜索词（URL 编码），`{page}` 换成页码；没有 `{page}` 时只取一页。搜索词也可以在路径里，如 `https://example.org/search/{keyword}/{page}`。

| 字段 | 说明 | 默认 |
|---|---|---|
| `html.item` | 每条结果的选择器 | 必填 |
| `html.title` | 条目里标题的选择器 | 条目里第一个链接的文字 |
| `html.link` | 详情页链接，`选择器@属性` | 条目里第一个链接的 `href` |
| `html.size` / `html.date` | 体积、时间的选择器 | 空：在条目文字里找"1.2 GB"、"2023-04-05"这样的文字 |
| `html.magnet` | 磁力的选择器（在详情页里也用它） | 空：找 `magnet:` 链接，没有时找 40 位 hash |
| `html.detail` | 列表里没有磁力时，打开详情页去找 | `false` |
| `html.detailLimit` | 每次搜索最多打开几个详情页（同时 3 个，结果按链接缓存） | 20 |
| `html.firstPage` | 第一页的页码 | 1 |

选择器支持：标签、`.class`、`#id`、`[属性]`、`[属性=值]`（以及 `^=`、`$=`、`*=`、`~=`）、`:first-child`、后代（空格）和子元素（`>`）组合、逗号并列。`选择器@属性` 取属性，不写 `@` 取文字；只写 `@href` 表示条目本身的属性。

网页站点的搜索页开了人机验证（如 Cloudflare）时插件打不开，会报"开启了人机验证"；这类站请在 Jackett / Prowlarr 里添加（配合 FlareSolverr），再用 Torznab 接入。

## 优选关键词（`keywords`）

```json
{
  "keywords": {
    "items": ["某发布组A", { "word": "某字幕组", "types": ["anime"] }, { "word": "某发布组B", "sources": ["Jackett"] }],
    "disable": ["rules.json 里的某个词"],
    "order": ["某字幕组", "某发布组A"]
  }
}
```

- `items`：每项是一个词，或 `{ word, sources, types }`。`sources` 限定只在哪些站点搜，`types` 限定只在哪些资源类型下搜；都为空表示不限。
- `disable`：停用下层（如内置）规则里的词。
- `order`：重排关键词，没列出的保持原顺序排在后面；配置页拖动排序写的就是它。

关键词的顺序就是优先级：搜索时排在前面的词的结果排在前面，其次才看站点顺序、分辨率和日期。

旧的 `publisherKeywords`（字符串数组）仍然认：非空时整体替换关键词列表，`keywords` 被忽略。配置页打开时会把旧版配置页里填的关键词迁移成 `keywords`。

## 一次搜索怎么用这些规则

1. 先定资源类型：抽屉里可以手动换；否则按 TMDb 类型判断（动画 → 动漫，纪录片 → 纪录片，剧集里的真人秀 / 脱口秀 → 综艺，其余为电影或剧集）。
2. 挑出负责这个类型的、开启的站点；一个都没有时改用全部开启的站点，并在抽屉里提示。
3. 每个站点只用适用于它和这个类型的关键词，按"站点 × 关键词"搜优选结果；结果不够时再按站点各做一次不带关键词的降级搜索。
4. 排序：关键词顺序 → 降级 → 站点顺序 → 分辨率 → 日期。"优选"标记表示命中了某个关键词。

## TMDb 地址（`tmdb`）

`tmdb.apiBases` 和 `tmdb.imageBases` 是配置页"TMDb 元数据地址""TMDb 图片地址"下拉框的候选项，每项是 `{ "value": 地址, "label": 显示文字 }`，第一项是默认值。插件直连这些地址，不经过中转；海报也由插件取回并缓存，浏览器只从 Jellyfin 加载。默认入口被屏蔽后，社区可以在内置规则里补充可用地址；用户也可以在覆盖文件里写一份新列表（数组整体替换），或在配置页选"自定义"直接填。

## 示例

发布版不内置任何资源站和优选关键词，站点都由用户在配置页添加，或写在 `rules.json` 里。

已添加的站点换了域名，只改地址（按 `name` 合并）：

```json
{
  "sources": [
    { "name": "my-api", "endpoints": ["https://新域名/search"] }
  ]
}
```

添加一个返回 JSON 的搜索接口：

```json
{
  "sources": [
    {
      "name": "my-api",
      "kind": "jsonApi",
      "endpoints": ["https://example.com/search"],
      "response": {
        "itemsPath": "results",
        "fields": { "infoHash": "btih", "name": "title", "size": "bytes", "createdAt": "date", "createdAtFormat": "iso" }
      }
    }
  ]
}
```

修正一个制片公司的 TMDb ID（数组整体替换，要写全）：

```json
{ "discover": { "companies": [ { "value": "174", "label": "华纳兄弟" } ] } }
```

## 以后

v6 方案里的规则订阅自动更新、第三方规则的签名校验还没做。现在配置页可以从订阅地址导入一次规则片段（写进配置页这一层），以后的自动更新会沿用这里的叠加规则。
