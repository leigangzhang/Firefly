# 萤火虫FireFly 目标市场定位分析

Oct 20, 2026 · @Zhang Ray

## 结论

**推荐定位：中国大陆的 Mac/NAS 家庭影院用户，不要求用户会翻墙；网络问题由插件架构解决，而不是由用户解决。** 理由是三条限制里只有法律风险是硬约束，网络和渠道都可以通过架构绕开；而大陆是唯一同时满足"迅雷能下、资源站是中文、用户愿意为省事付费"的市场。

但必须同时说清楚一件更关键的事：**市场选在哪里，都改变不了"收费工具 + 内置盗版资源站"这个组合本身的法律风险。** 你本人在国内，中国法律对你始终适用，卖给海外用户并不能规避；而国内已有人人影视创始人因传播美剧被判刑的先例。所以真正决定下一步的，不是"大陆还是欧美"，而是"授权码收费 + 规则文件由你维护资源站"这一商业模式要不要改。第五节给出了改法。

## 限制一：网络依赖

要求用户自己打通两地网络，会把大陆市场压缩到很小的一群人。但逐项看，在大陆不通的只有 TMDb 和 YouTube，而这两项都不是核心链路，可以由插件侧解决。

| 依赖 | 大陆无翻墙 | 海外 | 大陆侧可解法 |
| --- | --- | --- | --- |
| TMDb API 与海报图 | 不稳定，DNS 污染为主 | 通 | 你在海外服务器上反代并缓存（热门榜单一天更新一次就够）；或改用已备案的中转域名 |
| YouTube 预告片 | 不通 | 通 | 改为可选功能，大陆默认隐藏；或换 B 站搜索链接 |
| 资源站（diao.im 等） | 通 | 通 | 不需要 |
| 迅雷磁力下载 | 通（但热门片有版权拦截） | 你实测美国 IP 不可用 | 不需要 |
| Jellyfin 插件库 | 放国内对象存储即可（v5 已规划） | 通 | 不需要 |

反过来看海外：元数据和预告片天然可用，但迅雷这一环断了，必须换成 qBittorrent / Transmission 这类普通 BT 客户端。而 BT 下载时会同时上传，用户的 IP 会被版权方监控到，风险转到了用户身上（见第三节）。

结论：**网络不应成为筛选用户的门槛。** 一个海外小服务器反代 TMDb，就能让不会翻墙的大陆用户走通全流程。需要注意 TMDb 的 API 条款只允许非商业免费使用，收费产品要单独申请商业授权，这是另一个和"收费"绑定的问题。

## 限制二：需求规模

两地都有需求，但**愿意为 FireFly 这种形态付费的人几乎只在大陆**。下表是定性判断，没有可靠的公开用户数；括号里的是我记忆中的大致量级，未核实。

| 人群 | 现有方案 | FireFly 的差异化 | 付费意愿 |
| --- | --- | --- | --- |
| 大陆 NAS/Mac 用户 | MoviePilot（免费，依赖 PT 站邀请，配置重）、手动搜磁力 + 迅雷、网盘转存 | 不需要 PT、不需要 Docker、一键从榜单到入库 | 中。闲鱼上大量"NAS 代装、影视库搭建"服务说明有人为省事付费 |
| 海外华人 | 网盘、中文在线站、本地流媒体订阅 | 中文界面、中字资源 | 低。美剧韩剧在当地有正版，真正缺的是国产剧，但那不在 FireFly 的热门榜单里 |
| 欧美日韩本地用户 | Sonarr/Radarr + Prowlarr + Jellyseerr（免费开源，GitHub 星标各约一万级） | 轻量、装上即用：\*arr 要部署 4–5 个服务再互相对接，FireFly 只是一个 Jellyfin 插件。前提是换成英文资源源（Torznab）和 qBittorrent | 低。社区反感收费，但嫌 \*arr 太重的人会是一批免费用户 |

判断：欧美日韩本地用户不应直接排除：\*arr 是很重的部署组合（Sonarr、Radarr、Prowlarr、Jellyseerr、下载器各自配置再互相对接），FireFly 作为单个插件装上即用，这个差异化在海外同样成立。但它要等资源源解耦（Torznab）和 qBittorrent 适配完成才走得通，付费意愿也低，适合作为第二阶段的免费扩张，而不是首发市场。FireFly 真正的竞品是 MoviePilot，它的用户主要是有 PT 资格的老玩家；FireFly 的机会是"没有 PT、不会 Docker、用 Mac 的轻度用户"，这群人更大但也更不愿意折腾网络，这正是上一节要由插件解决网络的原因。规模可以先用低成本方式验证：在 V2EX、恩山、什么值得买、小红书发免费版，看一个月内的安装和反馈。

## 限制三：监管、法律与渠道

如实说：**按 v5 的形态（你维护并签名的规则文件指向盗版资源站 + 按下载额度收费），在大陆和海外都属于高风险，而且风险主要落在你本人身上，不在用户身上。** 以下是公开信息和常识层面的判断，不是法律意见，正式收费前建议找知识产权律师花一小时确认。

### 在大陆（对你始终适用，不论用户在哪）

- **刑事**：刑法第 217 条侵犯著作权罪的前提是"以营利为目的"，2021 年修正案（十一）把最高刑提到 10 年。人人影视创始人梁永平 2021 年被判 3 年 6 个月、罚金 150 万，涉及的正是美剧。国内也已有多起"影视聚合 App、盗链网站"开发者被追诉的案例。司法解释的入罪门槛大致是违法所得 3 万元或非法经营额 5 万元或作品 500 部，对一个卖授权码的产品并不高。
- **民事**：即使不存储任何视频，"明知资源侵权仍提供搜索、下载便利并收费"容易被认定为帮助侵权。你亲自维护、签名、推送指向特定资源站的规则文件，就是"明知"的证据。
- **渠道**：淘宝、闲鱼禁售侵权影视及主要用于侵权的工具，爱奇艺、腾讯等有专门团队举报；国家版权局"剑网"行动每年都点名这类商品。2026 年 7 月新华社还专门做了热播剧盗版调查（[新华网](https://www.news.cn/legal/20260729/eaf64b8efcd04fc888d4199d23b2aee0/c.html)），监管正在收紧。商品被下架只是最轻的结果，更麻烦的是订单和收款记录会直接成为"违法所得"的计算依据。爱发电、面包多同样是国内平台，规则类似。

### 在海外

- **开发者侧**：美国有 Grokster 案确立的"引诱侵权"责任，产品宣传和功能以盗版为卖点就会被追究。Kodi 插件库 TVAddons 的运营者被加拿大法院判罚（[Daily Hive](https://dailyhive.com/vancouver/tvaddons-fined-adam-lackman-canadian-court)），形态与 FireFly 很像：本身不存视频，只提供指向盗版源的插件。好莱坞联盟 ACE 在全球追踪这类工具，包括亚洲。
- **对居住在大陆的你**：海外民事判决很难执行到你本人，实际会发生的是：GitHub 仓库被 DMCA 下架、域名被停、PayPal/Stripe 等收款账户被冻结。所以"去海外非正式渠道推广被罚款"的概率不高，但"渠道与收款被断"的概率很高。
- **用户侧**：海外用户只能用 BT 客户端，下载即上传。德国用户会收到律师函索赔（常见千欧元级），美国会收到 ISP 警告，日本 2021 年起下载盗版也违法。产品会把用户直接暴露在这些风险里。

### 小结

你问"海外有没有类似淘宝的渠道"：没有。海外同类工具能长期存在的共同模式是：**免费开源、不内置任何资源源、由用户自己配置索引器**（Sonarr/Radarr/Prowlarr 都是这样）。这也是 MoviePilot 在国内的做法：不带 PT 站、不卖账号。这个模式才是风险的分界线，而不是市场所在地。

## 四种定位对比

大陆用户（由插件解决网络）在每一列上都不输于其他两个，而法律风险一列三者差别不大。

| 定位 | 全流程能否走通 | 需求与付费意愿 | 推广渠道 | 法律风险（对你） | 需要改的架构 |
| --- | --- | --- | --- | --- | --- |
| A. 大陆用户，插件代理元数据（推荐） | 能，无需翻墙 | 中；用户量最大 | 小红书、B 站、V2EX、恩山、什么值得买；不走淘宝闲鱼 | 高（如果收费且内置源）/ 低（如果免费且源由用户配置） | TMDb 中转、预告片可选 |
| B. 大陆会翻墙的 NAS 用户 | 能 | 低到中；人少且多已用 MoviePilot | 同上，更集中在 NAS 圈 | 同 A | 几乎不改 |
| C. 海外华人 | 要换掉迅雷 | 低；分散、有正版替代 | 微信群、小红书海外版、Telegram；收款难 | 同 A，另加收款账户被冻、用户收到索赔函 | 换 BT 客户端、做多平台 |
| D. 欧美日韩本地用户 | 要换迅雷和资源站 | 低；\*arr 免费但部署重，轻量是卖点 | Reddit、Discord，反感付费盗版工具 | 高，且 ACE 主动追踪 | Torznab + qBittorrent（NAS 支持本来就要做）+ 英文界面 |

B 和 A 的区别只是是否由插件解决网络。把门槛定在"会翻墙"会自己砍掉大部分潜在用户，而代价只是一台每月几美元的海外小服务器。

## 推荐定位对架构与商业模式的影响

定位 A 对代码的改动很小，对商业模式的改动很大。现有的 `IDownloader`、`IMediaHost`、规则驱动搜索都能保留。

### 架构

1. **TMDb 不替换，加一层中转。** 在海外小服务器上反代 API 和图片并缓存，插件配置页提供"直连 / 中转 / 自定义代理"三选一。豆瓣没有官方 API，不适合做主数据源。如果产品收费，要先向 TMDb 申请商业使用。
2. **YouTube 预告片改为可选。** 检测不到可达就隐藏，不影响主流程。
3. **迅雷保留为默认下载器，再加 qBittorrent / Transmission 适配器。** 这不是为了海外，而是为了群晖、绿联等 Linux NAS 上的 Docker 版 Jellyfin，那里调不到 Mac 迅雷。
4. **资源源与产品解耦（最重要）。** 插件本身不内置、不签名、不推送任何指向具体资源站的规则。用户在配置页自己添加"规则订阅地址"，和 Jellyfin 添加插件库、Prowlarr 添加索引器一样。同时支持 Torznab，可以直接接 Jackett/Prowlarr。

### 商业模式

- **去掉"按下载次数的月度额度"。** 它把每一笔收入和每一次盗版下载直接挂钩，是法律上最不利的设计。
- **如果要收费，只为中立功能收费**：多宿主（Emby）、剧集追更、自动整理入库与命名、中文字幕匹配、元数据中转服务等。这些对处理用户自己的合法片源也有用。
- **不走淘宝闲鱼，宣传不提片名和资源站。** 用中立的说法："家庭影院媒体库管理"。
- **代码仓库保持开源或至少不含源规则**，这样即使平台下架，产品本身不会消失。

这样做不能把风险降到零，但会把你从"卖盗版下载服务的人"变成"写了一个中立工具的人"，这正是 MoviePilot 和 \*arr 能长期存在的原因。代价是开箱体验变差：用户需要自己找一个规则订阅地址。

## 结合渠道调研的修正（2026-10-20）

你的闲鱼、淘宝、小红书调研支持"大陆优先"，也给了 FireFly 一个比"省事"更强的卖点：**自己的片库，不卡、不跑路、没有月费。** 但调研里最硬的成交数据属于内容库，不属于工具，不能直接算成 FireFly 的市场。

### FireFly 正好打在报告里的三个错配上

| 报告中的错配 | 共享 Emby 库的问题 | FireFly 的解法 |
| --- | --- | --- |
| 稳定不卡 | 带宽成本约 ¥8/Mbps，晚高峰必卡 | 下载到本地播放，没有带宽问题 |
| 不跑路 | 年卡跑路是常态 | 文件在用户自己硬盘里，买断即可 |
| 部署完还要自己找片源 | 教程和远程部署只管到装好为止 | 从榜单到入库一键完成 |

FireFly 的主要成本在开发，运营成本只有一台 TMDb 中转服务器，属于报告里"能规模化"的那一侧。

### 需要修正的地方

1. **市场规模要打折。** "1.98 万人付款""千万级 GMV"买的都是内容订阅。和 FireFly 直接可比的只有两类：一是一次性部署（¥49–358，月销百单级），二是工具（¥25–150）。按这个口径，工具细分的规模大概是内容库的十分之一甚至更小。这是我的推断，报告里没有工具类的成交数据。
2. **只支持 Mac 够不到这群人。** 报告里的小白和内容型用户买的是绿联、极空间、飞牛这类 NAS，上面跑的是 Docker 版 Jellyfin 或 Emby，调不到 Mac 迅雷。所以 NAS 支持要从 Phase 3 提前到公开发布之前：迅雷 NAS/Docker 版或 qBittorrent 适配器、飞牛或绿联的安装指南。Emby 兼容也要提前，因为报告里的生态大多是 Emby。
3. **卖点和法律风险在同一处。** 报告的第一需求是片源，但 FireFly 越是以"片源"为卖点，法律上就越接近报告里"不是跑路就是被抓"的库商。对外只讲"自动整理、追更、本地播放不卡"，资源源由用户自配，这条线不变。

### 定价与付费

- 报告里自建派拒绝订阅，小白一次性愿意付 ¥150 左右，工具的价格带是 ¥25–150。因此 FireFly 的付费功能适合**买断 ¥49–99**，不要做月费。"没有月费"本身就是和共享库竞争的理由。
- 报告里利润最厚的一段是一次性部署服务，但它靠人力、放大不了，和 FireFly 轻量、装上即用的定位相反。不做部署服务，FireFly 只通过产品本身变现。
- 投入产出的判断不变：先发免费版加赞助按钮，用安装量来决定。有了这份调研，发布地点可以更明确：小红书上搜"nas 片源怎么找"的人，和被共享库跑路伤过的人。

## 下一步

需要你先定一件事：商业模式是否从"授权码 + 下载额度"改为"免费核心 + 中立功能收费"。定下来之后的动作：

- [ ] 确定商业模式（见上一节）
- [ ] 把 diao.im 规则从插件内置和你的推送服务里移除，改为用户添加订阅（订阅场景较复杂，具体设计待评估）
- [ ] 搭 TMDb 中转并在一台不翻墙的大陆网络上实测全流程

  测试阶段用 Cloudflare Tunnel 把本机中转服务暴露出去，上线前再做云上部署和域名配置。
- [ ] 预告片改为可选
- [ ] 免费版在 V2EX / 恩山 / 小红书小范围发布，用一个月的安装量验证需求规模
- [ ] 如果仍要收费：咨询知识产权律师、申请 TMDb 商业授权
- [ ] NAS 支持提前：Docker 版 Jellyfin/Emby + 迅雷 NAS 版或 qBittorrent，先覆盖飞牛和绿联
- [ ] （后期附加功能）网盘离线 + STRM 下载器：只服务网盘会员用户，等调研显示网盘存储用户明显上升再提前
- [ ] 与免费版同时上线产品官网：功能介绍 + Mac/飞牛/绿联安装教程 + 插件库地址；SEO 关键词用"Jellyfin 插件""NAS 家庭影院""自动入库追更"，不用片名和资源站；放国内服务器需 ICP 备案（利于百度收录），放 Cloudflare Pages 免备案但百度收录弱；后期加英文版
- [ ] 设计元数据中转（反代 + 缓存），部署在现有 VPS（1 核 / 2GB / 50GB，20M 带宽、不限流量、已接 CDN）。要点：Caddy 或 Nginx 反代 TMDb API 和图片域名；JSON 按接口分别设缓存时间（榜单约 6 小时，详情约 1 天）；图片走 CDN 长缓存，源站缓存上限约 20GB；每个用户一个令牌并限速；TMDb Key 只放在服务器端；插件配置页提供"直连 / 中转 / 自定义代理"三选一；服务器只提供元数据，不分发规则
